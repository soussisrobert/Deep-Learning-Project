# claims.md

Format: **Claim** / Source file / Selection caveat. "Lost frame" everywhere below = a frame with a usable GT box whose predicted box centre (x + w/2, y + h/2) is more than 20 px from the GT centre (usable = GT w and h > 0). Success AUC = mean over IoU thresholds 0, 0.05, ..., 1 of the share of ALL frames with IoU above the threshold (absent-GT frames count as failures). "Own script, not the official toolkit" is stated where it applies; the official toolkit (pysot `OPEBenchmark` through `NATDataset`) produced only the per-video CSVs and the headline numbers.

## Why trackers lose the target (first_ag = first.pth + anchor 0.2 + gamma 0.6, NAT2021; own scripts)
9. **95% of lost-stretch starts have the target inside the search window: 864 of 909 stretches (95.0%) start with the GT centre inside the window.** / `tools/illumination/E15_stretches.csv` (column `gt_in_window_first_frame`), `output/output_E15_lost_diag.out`, script `tools/lost_diag.py` (own) / Window = square of side round(s_x) around the previous predicted box (s_z = sqrt((w+p)(h+p)), p = (w+h)/2, s_x = s_z x 287/127); "inside" is about the GT centre only. Over all 50,749 lost frames the GT centre is inside the window on 53.8%.
10. **86% of lost frames are in stretches of 101+ frames: 43,793 of 50,749 (86.3%); 85 stretches of 201+ frames hold 38,827 frames.** / `tools/illumination/E15_stretch_length_hist.csv`, `E15_stretches.csv` / Own script; a stretch = consecutive lost frames; 909 stretches, median length 3 frames.
11. **Template similarity (cosine of flattened backbone features of a template cropped at the GT box vs the frame-1 template, every 10th frame): lost 0.467, found 0.597 (mean), ROC AUC 0.737 [0.688, 0.784]; within-sequence AUC 0.611 [0.587, 0.638].** / `tools/illumination/E17_roc_auc.csv`, `E17_template_sim.csv`, `output/output_E17_template_sim.out` (own, `tools/template_sim.py`) / Oracle crops at the GT box (the tracker never has them); 5,066 sampled lost vs 8,619 found frames; found = centre error <= 20 px.
12. **At the first lost frame of a stretch a logged runner-up peak (2d or 2x) is within 20 px of the GT on 53.7% of starts [48.6, 58.7]; this falls to 27.5% [22.0, 33.6] at the 5th lost frame, 12.2% [7.4, 17.4] at the 20th and 4.7% [2.2, 7.8] over all lost frames of 101+ stretches.** / `tools/illumination/E22_A_start_categories.csv`, `E22_A_lost_frame_peaks.csv`, `output/output_E22_A_to_C.out` (own, `E22_loss_taxonomy.py`, E13 logs `tools/margin/NAT2021/first1.2_m_anchor`) / The 2d peak is a cell at least 2 grid cells from the top-1 and often decodes to nearly the same box; 96.5% of tracked control frames also have a 2d or 2x peak within 20 px, so this is not a measure of competing hypotheses. 909 starts, 137 sequences; 10 sequences hold 25% of lost frames.
