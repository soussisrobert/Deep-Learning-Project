The two [builders](<F:/Code/HiFT/patches/0005_build_positive_patch.py>) / [mask builder](<F:/Code/HiFT/patches/0006_build_mask_patch.py>) read upstream and write only their patch output. They do not apply patches. They are independently executed in tests to compare patched source bodies with isolated adapters.

```bash
git -C third_party/HiFT apply --check ../../patches/0001-transformer-layout-b2.patch ../../patches/0002-negative-pair-supervision-b2.patch ../../patches/0003-reject-unsupported-distributed-launch.patch ../../patches/0004-singleton-class-selector-b2.patch ../../patches/0005-empty-positive-support-b2.patch ../../patches/0006-mask-before-arithmetic-b2.patch
```

All six pass a combined check against the untouched pin. Patches alone are **not a complete corrected real-data trainer**: original dataset sampling has no identity guarantee. New B2 callers must use [identity-checked target construction](<F:/Code/HiFT/src/hift_research/corrections/positive_targets.py#L16-L44>) and supply canonical `(dataset,video,track)` keys. Missing or equal keys fail closed, without silent relabeling or unbounded resampling. The old Wave1 low-level pair-target constructor remains a compatibility primitive, not a verified sampler.

See [Wave2 G1 recommendation and unresolved concerns](<F:/Code/HiFT/reports/wave2_m1.md>).
